# 扣子工作流配置说明

## 输入节点

设置四个文本输入：

- `request_text`：用户需求或工作目标，必填；
- `document_text`：会议纪要、通知或业务材料，选填；
- `data_csv`：CSV 任务表或统计表，选填；
- `report_text`：周报、汇报或结论草稿，选填。

## 插件节点

调用插件“职效智办办公处理”，映射同名字段：

- `request_text` → `request_text`；
- `document_text` → `document_text`；
- `data_csv` → `data_csv`；
- `report_text` → `report_text`。

插件会按实际提供的输入执行需求理解、文档摘要、待办提取、表格检查和汇报依据提示，返回 `status`、`answer`、`tool_trace` 和 `agent`。

## 输出节点

把 `answer` 直接交给 Bot，并追加：

“以上是自动整理结果。发送、归档或据此作出业务决定前，请人工确认负责人、日期、数据口径、附件版本和隐私合规性。”

## 对话流程

1. 用户没有需求时，提示补充要完成的办公任务；
2. 只有需求时，完成需求理解和待办线索提取；
3. 需求加办公材料时，展示摘要、待办和待确认项；
4. 需求加 CSV 时，展示字段、缺失、重复和候选异常提示；
5. 同时有 CSV 和汇报材料时，展示结论依据的初步匹配；
6. 对插件错误只返回缺少什么输入或稍后重试的说明。

## 演示验收

准备三组脱敏输入：

1. 会议材料：验证摘要和待办提取；
2. 任务表：验证缺失、重复和候选异常提示；
3. 任务表加周报：验证结论与表格的依据提示。
